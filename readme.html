01 Arranque de los servicios

Todo corre con Docker Compose. El stack base levanta PostgreSQL, el backend y el frontend con hot-reload. MinIO es un perfil aparte y solo hace falta si vas a subir fotos o media.

  1. Preparar el entorno una sola vez

    Copiá el archivo de ejemplo. Los valores por defecto alcanzan para desarrollo local.

    Terminal
    # desde la raíz del repo
cp .env.example .env

  2. Levantar el stack base

    PostgreSQL + backend (Spring Boot) + frontend (Vite). La primera vez compila las imágenes.

    Terminal
    docker compose up -d --build

  3. Opcional: habilitar MinIO

    Necesario para fotos, avatares y cualquier media. Sin este perfil el almacenamiento de archivos no está disponible.

    Terminal
    docker compose --profile minio up -d --build

  4. Verificar que todo esté arriba

    El backend espera a que PostgreSQL esté healthy. El frontend espera al backend.

    Terminal
    docker compose ps
docker compose logs -f

./mvnw spring-boot:run
Frontend

npm install
npm run dev

El frontend dentro de Docker ya tiene hot-reload: editás en frontend/src/ y se recarga solo. Si corrés npm run dev fuera de Docker, Vite escucha en http://localhost:8081 según vite.config.ts; el mapeo 5173 es el del contenedor.

Lo que NO se siembra: orden de creación manual

Después del primer login, hay dependencias duras: una planta no existe sin cepa ni sala.

Paso 1

Cepa

Genética. Obligatoria: Planta.cepa_id es NOT NULL.

Paso 2

Sala

Cuarto de cultivo. Obligatoria: Planta.sala_id es NOT NULL.

Paso 3

Zona opcional

Grilla dentro de la sala. La planta se ubica por columnaEnZona / filaEnZona.

Paso 4

Planta

Etapa inicial: germinación, plantín, vegetación, floración o cosechada.

Paso 5

Nutrientes opcional

Necesarios antes de registrar un evento de tipo NUTRIENT.

Paso 6

Eventos

Riego, cambio de etapa, notas, poda, defoliación, medición, nutrientes.

🧪

No hay mocks de frontend. No existe MSW, ni src/mocks/, ni fixtures, ni flag VITE_USE_MOCK. El frontend siempre habla contra el backend real.

No hay data.sql ni migraciones. El esquema lo administra Hibernate con ddl-auto=update; no hay Flyway ni Liquibase.

05 Stack en una vista

Tres capas, sin servicios externos obligatorios más allá de PostgreSQL.

Frontend

React + Vite

React 18.3 · TypeScript 5.8 · Vite 5 (SWC) · react-router-dom 6 · TanStack Query 5 · Zustand 5 · axios · zod 4 + react-hook-form · Radix/shadcn · Tailwind 3.4 · Recharts · framer-motion · sonner.

Backend

Spring Boot

Java 21 · Spring Boot 3.5.6 · Spring Security (JWT stateless) · Spring Data JPA / Hibernate · springdoc OpenAPI · MinIO SDK 8.5.9 · Spring Mail · Actuator · Log4j2 · Lombok.

Infraestructura

Docker

Docker Compose · PostgreSQL 15-alpine · MinIO · multi-stage Dockerfiles · Nginx para el frontend de producción · volúmenes persistentes para DB y media.

Seguridad y sesión

JWT en memoria + refresh HttpOnly

El access token vive en memoria (no en localStorage). El refresh viaja en cookie HttpOnly y se renueva al recargar.

Sesiones multi-dispositivo

Cada dispositivo registra deviceInfo, ipAddress y userAgent, con revocación individual.

Validación de respuestas

Zod valida los DTOs que llegan del backend en runtime, no solo en tiempo de compilación.

Roles

ROLE_SUPER_ADMIN · ROLE_ADMIN · ROLE_GROWER. El panel de administración exige admin o superior.

09 Notas y discrepancias conocidas

Cosas que la documentación vieja dice distinto del código real. Verificado contra el repo.
