🛡️ 3. Seguridad Frontend — Defensa en Capas

📋 Matriz de Amenazas

AmenazaMitigación ActualEstado
XSS (Cross-Site Scripting) React escapa output por defecto · Sin dangerouslySetInnerHTML 🟢 Bueno
XSS en rich text No hay rich text inputs aún — preparar DOMPurify 🟡 Preparar
JWT robado (XSS) JWT en HttpOnly cookie — inaccesible desde JS 🟢 Excelente
CSRF Cookie SameSite + withCredentials 🟢 Bueno
Man-in-the-Middle HTTPS (asumido en producción) 🟢 Estándar
Inyección en queries Zod valida tipos en requests salientes 🟢 Bueno
Session hijacking Sin refresh token aún 🟡 Mejorable
Clickjacking Sin frame-ancestors CSP aún 🔴 Ausente

📊 5. Health Check

✅ Buen Estado

  • Separación de módulos clara y por dominio
  • Arquitectura Backend-First con Zod como fuente de verdad
  • Autenticación JWT HttpCookie (no accesible desde JS)
  • Estado global mínimo y bien estratificado
  • Componentes reusables shadcn/ui + composición por dominio

🟡 Atención Media

  • TypeScript laxo (strictNullChecks: false, noImplicitAny: false)
  • Sin CSP headers ni DOMPurify
  • Sin code splitting ni lazy loading
  • Eventos sin validación Zod
  • ProductContext.jsx en medio de todo TypeScript

🔴 Riesgo Alto

  • Cero tests — sin Vitest, Playwright, ni Testing Library
  • Datos de cultivo sin validación automatizada
  • Sin seguridad de contenido (Content Security Policy)
  • Sin refresh token rotation

🔗 6. Dependencia con Backend

📤 Request Flow

  • Axios con withCredentials: true → cookie JWT se envía sola
  • Content-Type: application/json (o multipart/form-data para fotos)
  • URL base via VITE_API_URL = 12factor compliant

📥 Response Flow

  • Zod safeParse valida cada respuesta del backend
  • Si el contrato se rompe → error + toast al usuario + consola
  • HTTP 401 → logout automático global
  • validateResponse() genérico para mutaciones POST/PUT

✅ 7. Conclusión

🏆 Fortalezas

  • Arquitectura modular real — folder-by-domain, no folder-by-type
  • Backend-First con validación runtime — detección temprana de contratos rotos
  • Auth security-first — JWT en HttpOnly cookie, sin localStorage
  • Estado bien estratificado — React Query + Zustand + Context
  • Componentes reusables — shadcn/ui + composición por dominio
  • Multi-tab sync con BroadcastChannel

⚠️ Debilidades a Abordar

  • TypeScript laxo — strictNullChecks: false es una bomba de tiempo
  • Cero tests — para datos de cultivo, es el riesgo #1
  • Sin CSP ni DOMPurify — seguridad de contenido necesita atención
  • Sin code splitting — bundle crece sin lazy loading
  • Eventos sin validación Zod — schemas de eventos no cubiertos
  • Sin role-based route guards — solo ProtectedRoute genérico
